I discovered mapgl while working with geospatial data at AstraZeneca, where I was building an in-house solution for sales territory and workforce planning for a new product and team launch. Being able to put data on a map, explore it interactively, and explain what the geography meant made it much easier to connect an analysis to a practical decision.

This tutorial brings that approach into DATA1X01 Project 2. You will learn how to turn a table or spatial file into an interactive map, embed it in your Quarto report, and explain the pattern it shows. You do not need previous experience with geographic information systems.

NoteHow the examples work

The maps below are actual outputs of the R code, rather than screenshots. Drag to pan, use the + / − buttons to zoom, and try the popups and other controls. Mouse-wheel zoom is disabled in most examples so you can scroll through the lesson comfortably.

R runs when Quarto renders this page. The published maps run JavaScript in your browser. To change the R code and recompute an example, download the source and run it in RStudio. A static website does not provide a live R session. These examples use MapLibre and OpenFreeMap without an API key; the basemap still needs an internet connection.

Our real Sydney case study

We will use Greater Sydney, as defined by the ABS Greater Capital City Statistical Area (1GSYD). This includes the Central Coast and Blue Mountains; it is broader than the City of Sydney council area. The polygon maps use 373 real Statistical Areas Level 2 (SA2s). An SA2 is a statistical area, not necessarily a suburb or a school catchment.

You need either coordinates, geometries, or an identifier that can be joined to boundaries. A place name on its own is not a geometry.

sf adds a geometry column to the table. coords identifies the coordinate columns, and crs = 4326 declares that these are WGS84 longitude and latitude in degrees. Use that declaration only when it matches the source metadata. remove = FALSE keeps the coordinate columns for inspection.

Range checks catch obvious errors, but cannot prove that a valid coordinate is the correct one. Check the map’s extent against your study area, look for swapped columns, and investigate suspicious points. The NSW dictionary describes latitude and longitude but does not specify their geodetic datum; this teaching example treats them as WGS84 web coordinates. Do not use that assumption for survey accuracy or legal boundary decisions.

Understand coordinate reference systems

A coordinate reference system (CRS) describes what your coordinate numbers mean. Geographic coordinates use angular units; projected coordinates often use metres. Inspect an imported file’s CRS and geometry type:

st_crs(schools)$input
[1] "EPSG:4326"
unique(st_geometry_type(schools))
[1] POINT
18 Levels: GEOMETRY POINT LINESTRING POLYGON MULTIPOINT ... TRIANGLE
st_bbox(schools)
     xmin      ymin      xmax      ymax 
150.23258 -34.32048 151.58244 -33.13547

If a spatial file has a known projected CRS, convert its coordinates with st_transform(x, 4326) before passing it to a web map. Assigning a CRS and transforming coordinates are different operations. st_set_crs() changes the declared meaning of the existing numbers; it does not recalculate them. If the CRS is missing, find the original metadata before assigning one.

For the following import patterns, replace the paths with your own existing files. These are intentionally unexecuted templates.

areas <- st_read("data/my-boundaries.geojson", quiet = TRUE)
stopifnot(!is.na(st_crs(areas)))

# A GeoPackage can contain several layers.
st_layers("data/my-geography.gpkg")
roads <- st_read("data/my-geography.gpkg", layer = "roads", quiet = TRUE)

# For projected CSV coordinates, use the CRS stated by the data provider.

                            crs = verified_source_crs)

The sf import reference covers supported file formats; the st_transform() reference explains transformations. For distance, buffers, or area calculations, choose an appropriate analytical CRS or understand sf’s geographic calculation methods. Do not interpret degrees as metres.

Category colours and proportional circles

We group primary and infants schools together, retain secondary schools separately, and put the provider’s remaining categories in an explicitly labelled group. The original school type remains in the popup. For proportional circles, area should represent enrolment, so radius is proportional to the square root of FTE.

school_groups <- c("Primary / infants", "Secondary", "Other government sites")
school_colours <- c("#0072B2", "#D55E00", "#009E73")
schools <- schools |>
  mutate(school_group = case_when(
    school_type %in% c("Primary School", "Infants School") ~ school_groups[1],
    school_type == "Secondary School" ~ school_groups[2],
    TRUE ~ school_groups[3]
  ))

# Missing enrolment is not zero. Keep those locations in the basic map,
# but account for their exclusion from this quantitative encoding.
schools_known <- schools |> filter(!is.na(enrolment_fte))
stopifnot(all(is.finite(schools_known$enrolment_fte)),
          all(schools_known$enrolment_fte >= 0))
schools_known <- schools_known |>
  mutate(radius_px = 6 * sqrt(enrolment_fte / 500))

data.frame(all_locations = nrow(schools),

Why map density rather than population count?

A large SA2 can contain many people spread over a large area. Population density is population / area_km2, measured in residents per square kilometre. It answers a question about geographic concentration. A count answers a question about how many residents an area contains. Neither is a measure of school access or capacity.

We use the official ABS area_albers_sqkm value, renamed area_km2. We do not recompute area from the simplified display polygons. The denominator includes the area represented by the ABS boundary definition; density does not mean that population is evenly spread inside the polygon.

9. Use a spatial join when there is no area code

The school table has coordinates but no SA2 code. A spatial join attaches the code using location. Use the full-resolution analytical boundaries for this operation, not the simplified display copy.

# EPSG:28356 is GDA94 / MGA zone 56; it is not a universal choice.
schools_local <- st_transform(schools, 28356)
sa2_local <- st_transform(sa2_full, 28356)
memberships <- st_within(schools_local, sa2_local)
membership_count <- lengths(memberships)

17. Adapt the workflow to Project 2

Start with the analytical question, then choose a geometry and an encoding that help answer it. For example, point locations can support a question about distribution, while area rates can support a comparison between regions. The appearance of the map should follow from that question.

  1. Identify the geographic unit. Is each row a location, an event, a route, or an area? Check the data period and coverage.
  2. Prepare and validate the data. Read files reproducibly, verify the CRS, inspect invalid or empty geometries, and account for excluded rows.
  3. Join only what is needed. Check unique identifiers and unmatched keys. Keep only columns that are appropriate to publish.
  4. Choose the encoding. Use category colours for categories, a sequential scale for a rate, or proportional circle areas for suitable counts. Explain the units.
  5. Write the finding. Describe a relevant pattern, quantify it, and discuss the source’s limitations. Pair the map with a chart or table when precise comparison matters.
  6. Render and check the result. Make sure the HTML opens and the map works in the same format the reader or marker will receive.

Performance and responsible publication

Every attribute retained in a displayed sf object may be serialized into the map’s GeoJSON. Hiding a column from a popup does not remove it from the published HTML. Select only approved fields before mapping, and do not publish confidential data or precise personal locations.

For a slow map, first reduce unnecessary columns, crop to the study region, and inspect file size. Simplify a display copy of large geometries using a defensible tolerance; retain the originals for analysis. A clustering control reduces visual crowding but still sends the underlying points to the browser. Large projects may need vector tiles or PMTiles rather than an embedded GeoJSON dataset.

Keep basemap attribution visible. Provide a useful caption and a table or chart so that colour perception, a small screen, or an unavailable basemap does not prevent a reader from understanding your result. Avoid adding many maps when one answers the question clearly.

18. Troubleshoot common problems

Symptom What to check
The basemap appears, but no data do Check st_bbox(), longitude/latitude order, CRS, geometry type, and whether a filter excludes everything.
Points appear in the wrong country Check swapped coordinates and the source CRS. Projected eastings and northings are not longitude and latitude.
Nothing appears in the report Finish the chunk with the map object, set a non-zero height, and render to HTML. Check chunk output options.
Grey or unexpected colours Inspect missing values, column types, exact category spelling, and expression defaults.
A join adds many extra rows Check duplicate keys and whether a spatial predicate matches multiple areas.
A join loses areas Inspect unmatched keys in both directions, identifier types, leading zeros, and boundary vintage.
A slider shows no features Make the property numeric, check the layer ID, and check its range and selected value.
The layer control changes nothing Supply layer IDs, rather than source IDs; group related fill and outline layers.
could not find function Load the package and check its version. These examples use mapgl 0.5.2 or later.
sf or terra will not install Use an appropriate binary where available. Linux source installs need geospatial system libraries; see each package’s official installation guidance.
The whole map stays blank Check the browser console, WebGL availability, internet access, basemap service, and website security policy. Try another current browser.
The published page loses its maps Publish the rendered HTML with its dependencies, or use embed-resources: true. Source .qmd alone is not a rendered page.
The map works online but fails offline Its basemap is remote. Embedded dependencies do not make remote tiles available offline.
